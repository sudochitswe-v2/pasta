# Implementation Plan: Virtual HID & Secure App Bypass

This plan outlines the steps necessary to implement the features described in the recent changelog, introducing a "Stealth Type" injection mode designed to bypass secure applications and anti-cheat systems.

## Phase 1: API Updates & Translation Engine

### 1.1 New API Endpoint
- **Task:** Implement `POST /api/type` endpoint in `server/server.go`.
- **Details:** 
  - This endpoint will receive strings and trigger the new raw Virtual HID keystroke translation.
  - Ensure this remains distinct from the existing `POST /api/paste` (which uses the clipboard).

### 1.2 Payload Translation Engine
- **Task:** Create a translation engine to map strings to raw hardware events.
- **Details:**
  - Build a character-to-scancode mapping system.
  - Implement modifier key handling (e.g., translating `!` into `Shift (Down) -> 1 (Down) -> 1 (Up) -> Shift (Up)`).
  - Add configurable micro-sleeps (1-5ms) between keystroke events to prevent input dropping in polling-based secure apps.
  - *File Location:* Likely a new package `translator/` or within the `injector/` package.

## Phase 2: OS-Specific Injection (Stealth Type)

### 2.1 Linux Implementation (Virtual HID)
- **Task:** Upgrade Linux injection in `injector_linux.go` to fully utilize `/dev/uinput`.
- **Details:**
  - Ensure the daemon registers as a native virtual hardware keyboard (`EV_KEY`).
  - Send raw scancodes generated by the Translation Engine.
  - Verify that this completely bypasses Wayland/X11 user-space restrictions.

### 2.2 Windows Implementation (KMDF Integration)
- **Task:** Replace `user32.dll` (`SendInput`) with Kernel-Mode Driver (KMDF) integration in `injector_windows.go`.
- **Details:**
  - Integrate a KMDF solution (such as the Interception API or Nefarius/ViGEmBus).
  - Use this driver to strip the `LLKHF_INJECTED` flag, which is used by anti-cheat systems and secure apps to block simulated inputs.
  - Handle driver installation dependencies and initialization within the application lifecycle.

## Phase 3: Integration & Testing

### 3.1 Dual Injection Modes integration
- **Task:** Refactor the injection logic to support both "Fast Paste" (Clipboard + `Ctrl+V`) and "Stealth Type" (Virtual HID) cleanly.
- **Details:** 
  - Update interfaces in `injector/injector.go` to support switching between the two modes based on the triggered API endpoint.

### 3.2 Testing against Secure Apps
- **Task:** Verify the "Stealth Type" implementation successfully bypasses restrictions.
- **Details:** 
  - Test in environments known to block `SendInput` (Windows) and X11/Wayland simulated events (Linux). 
  - Ensure micro-sleeps are effective in preventing dropped inputs.
